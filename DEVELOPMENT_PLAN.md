# Development plan and phase gates

Current deliverable: Phase01 documentation/acquisition/validation only. Existing editor configuration is not a playable game. The [README](README.md), [review](docs/qa/PREPRODUCTION_REVIEW.md) and [blockers](docs/qa/BLOCKERS.md) report actual completion and evidence. A requirement record or narrative document never constitutes a tested asset.

## Phase01 acceptance gate

1. Canonical STORY plus seven treatments, six complete screenplay scenes with actual lines, shot lists and blocking.
2. Six mission specifications, five metric environments, characters, animation/co-op/pipeline/scene architecture requirements.
3. Every required asset ID in manifest; legal originals with checksum/license, separate runtime derivatives, honest missing items.
4. Import/resource loading tested where installed tools support it; visual, rig, motion and audio checks reported individually with evidence. NOT TESTED never promoted to PASS.
5. Independent QA cross-checks links, dialogue IDs, objectives, timeline, inventory, asset IDs and licenses. Corrections rereviewed up to five cycles; unresolved critical issues explicitly block production readiness.

Documentation completion can pass while art readiness remains BLOCKED. Root status must distinguish those outcomes. Documenting all gaps completes a handoff report, but does not complete Phase01 asset-ready acceptance. Phase01 remains incomplete while required production assets or verification are blocked; asset-ready approval requires verified rigs, contacts and environments as well as review. Acquiring a few CC0 textures cannot certify a prison kit or character pipeline.

## Future complete game and online work

Chapters2–7 need production scripts, layouts and inventories from their treatments before implementation. Online introduces authority, reconnect, save migration and latency testing; local scene ownership must make that possible without promising free conversion. Security and session service decisions await scope approval.

## Change control and handoff

README first, then STORY, relevant mission/environment, manifest and validation. A change to a scene updates screenplay/dialogue/shot/blocking/mission together; changed prop custody updates story continuity and checkpoint schema. New source files require license and checksum. Never overwrite original archive. Each change records affected IDs, verification performed, untested limits and reviewer disposition. Future agents must rerun appropriate checks and update README progress. Do not begin gameplay while treating Phase01 missing assets as complete.
