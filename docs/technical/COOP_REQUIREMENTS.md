# Cooperative requirements

Design only; Phase01 contains no co-op gameplay implementation. P1 Adrian, P2 Noah. Initial Windows local two-player vertical split-screen, two independent third-person cameras and input contexts. Proposed input: two gamepads preferred; keyboard/mouse+one gamepad fallback. Device ownership must be explicit before play; disconnect pauses both and offers reassignment. UI/pause/subtitles must remain legible at half1080p width, adjustable font and safe margins.

Both player roots inhabit one authoritative world. Separate SubViewports render the same World3D; shared audio listener at conversation anchor proposed, with per-view positional mix tested later. Do not run duplicate mission/NPC simulations per viewport. No player can consume another's interaction accidentally. Interaction leases use playerID+objectID+state, with ready/active/release/cancel and atomic state commits. Partner waiting never drains health or silently expires an essential story opportunity.

Mission co-op matrix: M01 parallel badge/property observations; M02 mediation/ball distraction; M03 isolation/inspection then diagram halves; M04 lookout/rear fastener then hatch clearance; M05 brake/selector with handsets; M06 dual handles and independent solitary pipe response. Every gate requires the two distinct actors. Critical information is replayable/captioned; physical separation does not demand external voice chat. Online future design should add optional authored ping/call prompts, with no new dialogue invented during implementation.

Cinematics: both ready before locking, full-screen shared presentation, both control contexts suspended; joint skip commits same story state. Pausing/disconnect stops cinematic clock. Gameplay return blends both cameras0.4s. Dialogue queues prevent conflicting intelligible lines; optional barks never cover clues. During separation, subtitles identify speaker/source and stay visible to both where narrative requires shared knowledge.

Checkpoint transaction snapshots: mission ID, CPnn_A/B, schema version, both transforms/route, inventory owner, prop states, door/puzzle state, patrol phase, objective flags, character knowledge, consumed dialogue, story decisions. Save only stable states; never halfway through door motion or item transfer. Retry restores both atomically. CP04 detection always returns CP04_A; capture M06 is authored progression. CP06_B is solitary before pipe response. No evidence appears in inventory if inspected in place; photo approved paper carried in Noah shirt; other property locker42, diagram returned, ledger console, shim confiscated.

Future online: authority validates interactions/objective commits, reliable ordered story events with unique event IDs, clients predict locomotion only. Avoid frame-based timing for co-op gates; use authoritative state and grace windows. Network reconnection, ownership transfer, save migration, latency/packet loss and security are future requirements, not delivered capabilities. No promise of online release in Phase01.

Next phase acceptance tests: both device ownership, one-player cannot solo gate, held control release safely pauses, simultaneous inputs idempotent, disconnect/reconnect, skip by mutual consent, reload before/after pickup, both viewport camera collisions, captions, low vision contrast, 30/60fps state equivalence, eventual latency simulation.
